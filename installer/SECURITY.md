# 安全策略

## 为什么这个项目需要单独的安全策略

wind-installer 生成的安装器运行在最终用户的机器上，并且通常**以管理员权限执行**：写注册表、
向 `%WINDIR%\Fonts` 安装字体、注册 COM 组件、创建快捷方式、排队重启后删除文件。
这类组件中的缺陷可能被用于提权或持久化，因此我们希望相关问题在修复前不要公开。

## 支持范围

安全修复只针对 `main` 分支和最新的 Release。旧版本不做回溯修复。

以下**属于**本仓库的安全问题：

- 安装/卸载过程中的权限提升、路径穿越、符号链接或目录联接攻击
- 归档解析中的内存安全问题，或可被构造的恶意归档触发的越界写入
- 卸载残留导致的权限放大（例如遗留了权限过宽的目录或注册表项）
- 打包工具 `wind-packer` 在处理不受信任的输入时的缺陷

以下**不属于**：

- 用某个应用的清单打出的安装包在该应用侧引发的问题——请报告给该应用的仓库
- 杀毒软件对安装器的误报（属于常规 Issue，见 `docs/DESIGN.md` 的「Anti-Virus 对策」一节）
- 需要攻击者已经具备管理员权限才能成立的场景

## 报告方式

**请不要通过公开的 Issue 报告安全漏洞。**

请使用 GitHub 的私密漏洞报告功能：进入本仓库的
[Security 标签页](../../security/advisories/new)，点击 “Report a vulnerability”。
该渠道只有仓库维护者可见。

报告中请尽量包含：

- 受影响的组件（安装器 / 卸载器 / wind-packer）与版本
- 触发问题的清单片段或构造出的归档文件
- 复现步骤，以及攻击者需要具备的前提条件（是否需要本地账户、是否需要用户交互）
- 你评估的影响范围

## 处理流程

1. 我们会在收到报告后尽快确认，并在私密通告中与你沟通进展
2. 确认问题后着手修复，必要时会与受影响的下游使用者协调发布节奏
3. 修复发布后公开安全通告；如你愿意，会在通告中致谢

感谢你负责任地披露安全问题。
